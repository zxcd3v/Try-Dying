# Архитектура решения

## Контекст

Задача — передать файл между двумя ноутбуками **только звуком**: динамик
одного играет, микрофон другого слушает. Ни сети, ни кабелей, ни общей
файловой системы. Условия демонстрации заранее неизвестны: от тишины до
сильного шума в зале, дешёвые встроенные тракты, эхо помещения, расхождение
кварцев звуковых карт, обработка звука Windows.

Из этого следуют три опорных требования, которым подчинена вся архитектура:

1. **Приём должен переживать шум** — сигнал читается по частоте, а не по
   амплитуде или фазе (ADR-0001).
2. **Потеря куска не должна ронять передачу** — каждый аир-кадр
   самодостаточен, добор потерянного идёт списком (ADR-0002).
3. **Результат должен быть доказуем** — вердикт стороны приёма основан на
   SHA-256 исходного файла, а не на «вроде похоже».

Термины (блок, кадр, партия, полоса, профиль) — [CONTEXT.md](../CONTEXT.md),
он же словарь для кода, тикетов и доклада.

## Компоненты

Два слоя с жёсткой границей — контракт v1.2 (`send_blocks` /
`receive_blocks` / `PROFILES` / `MAX_BLOCK` + калибровка):

```
        файл                                   файл
          │                                      ▲
   ┌──────▼───────────────┐            ┌─────────┴────────────┐
   │ Протокол (protocol/) │            │ Протокол (protocol/) │
   │ zlib → кадр → RS     │            │ RS → CRC32 → сборка  │
   │ NACK-цикл, SHA-256   │            │ NACK/DONE, SHA-256   │
   └──────┬───────────────┘            └─────────▲────────────┘
          │ блоки байтов (контракт v1.2)         │ блоки байтов
   ┌──────▼───────────────┐            ┌─────────┴────────────┐
   │ Модем (modem/) TX    │            │ Модем (modem/) RX    │
   │ байты → MFSK-символы │            │ FFT → символы → байты│
   └──────┬───────────────┘            └─────────▲────────────┘
          │ сэмплы 48 кГц                        │ сэмплы 48 кГц
       динамик ──────────► воздух ──────────► микрофон
```

**Модем (`modem/`) — «глупая труба».** Не знает, что внутри блока, и не
проверяет целостность; обязан лишь сохранить длину и порядок байтов.

| Файл | Роль |
|---|---|
| `profiles.py` | все параметры сигнала: тона, длительности, пороги, полосы. Единственное место тюнинга |
| `framing.py` | аир-заголовок кадра: длина блока ×3 + CRC-8, приём по большинству |
| `tx.py` | блоки → сэмплы: chirp-преамбула, заголовок, символы, пилоты, паузы |
| `rx.py` | сэмплы → блоки: поиск преамбулы корреляцией, FFT окна символа, argmax |
| `probe.py` | зонд калибровки: мультитон и измерение SNR всех полос одним FFT |
| `channel.py` | симулятор канала для тестов: шум, дрейф часов, эхо |
| `audio.py` | живой звук: `sounddevice` наружу, полудуплекс, потоковый демодулятор |

**Протокол (`protocol/`) — надёжность и смысл.**

| Файл | Роль |
|---|---|
| `frames.py` | протокольный кадр (magic/type/seq/total/len/payload/CRC32) + Reed-Solomon |
| `transfer.py` | `FileSender` / `FileReceiver`: zlib, нарезка, NACK-цикл, SHA-256-вердикт |
| `calibration.py` | рукопожатие выбора полосы поверх служебных кадров (ADR-0003) |
| `spool_modem.py` | тот же контракт без звука: блоки ходят файлами через каталог-линк |
| `fake_modem.py` | оба конца в одном процессе с управляемой порчей — только для тестов |
| `corruption.py` | модель порчи канала для спул- и фейкового модема |

**CLI.** `send.py` и `recv.py` — два процесса, общий код в `cli_common.py`
(конфиг, флаги, прогресс, вердикты, дослуживание DONE). Пути и значения по
умолчанию читаются из `config/audiomodem.env`, флаги их перекрывают.

**Инструменты (`tools/`).** `bench.py` — стенд и таблица результатов,
`afr_sweep.py` — АЧХ тракта, `fast_probe.py` — диагностика поднесущих
профиля fast, `snr_grid.py` — пороги SNR, `mic_meter.py` / `speaker_test.py` —
проверка железа, `make_wav.py` — WAV и спектрограмма для доклада.

**Тесты (`tests/`).** 133 теста, звуковое железо не нужно: петля
tx → канал-симулятор → rx, полный протокол через фейковый модем и
интеграционные прогоны настоящих `send.py` / `recv.py` двумя процессами.

## Основные технические решения

Каждое решение записано отдельным ADR — там контекст, отвергнутые
альтернативы и последствия.

| Решение | Почему так | ADR |
|---|---|---|
| **MFSK**: символ = номер тона в сетке, приём — FFT окна символа | амплитуда гуляет от AGC и расстояния, фазу рушат эхо и дрейф часов; пик частоты виден сквозь шум и не сдвигается эхом | [ADR-0001](adr/0001-mfsk-modulation.md) |
| **Партия + NACK** вместо подтверждения каждого кадра | разворот «динамик↔микрофон» стоит 0.5–1 с; stop-and-wait упирается в ~150–250 Б/с даже в тишине | [ADR-0002](adr/0002-batch-nack-and-self-contained-frames.md) |
| **Самодостаточный аир-кадр**: своя преамбула и заголовок с длиной | дрейф часов не накапливается, потеря кадра локальна, добор — списком | [ADR-0002](adr/0002-batch-nack-and-self-contained-frames.md) |
| **Адаптивная полоса по зонду**: один мультитон, одно измерение SNR всех полос | АЧХ «динамик → комната → микрофон» имеет провалы в заранее неизвестных местах; перебор полос пакетами удлинил бы рукопожатие в ~10 раз без пользы | [ADR-0003](adr/0003-adaptive-band-calibration.md) |
| **Fast = 9 параллельных 4-MFSK-поднесущих** | у одиночного MFSK скорость ~`W·b/2^b`, максимум при b ≤ 2; вверх — только параллельные тона | [ADR-0004](adr/0004-fast-parallel-subcarriers.md) |
| **Служебные кадры всегда robust на якорной полосе** | канал управления не должен зависеть от результата калибровки: сорвалось рукопожатие — теряем секунды, а не сеанс | [ADR-0003](adr/0003-adaptive-band-calibration.md) |
| **zlib → Reed-Solomon → CRC32 → SHA-256** | RS чинит точечные битовые ошибки на месте, CRC32 отбраковывает то, что RS не спас, SHA-256 доказывает результат целиком | [PROTOCOL.md](PROTOCOL.md) |

Почему именно **1.5–9.5 кГц**: ниже 1.5 кГц живут голос и гул зала, выше
~10 кГц дешёвые тракты заваливают АЧХ, а 48 кГц дают запас по Найквисту.
Внутри окна сетка тонов кратна ширине FFT-бина профиля — иначе энергия тона
размазывается по соседним бинам и пик тонет в шуме.

## Зависимости

Python 3.11+ (`pyproject.toml`):

| Пакет | Зачем |
|---|---|
| `numpy` | сэмплы, FFT, корреляция — весь DSP |
| `scipy` | оконные функции и вспомогательный DSP |
| `sounddevice` | доступ к динамику и микрофону (PortAudio) |
| `reedsolo` | Reed-Solomon поверх блока |
| `pytest` (dev) | тесты |
| `matplotlib` (dev) | спектрограммы и графики АЧХ для доклада |

`sounddevice` импортируется **лениво**, внутри функций `modem/audio.py`: без
флага `--audio` звуковое железо не требуется вовсе — спул-демо и все тесты
идут на машине без звуковой карты.

## Безопасность и приватность

- **Сети нет.** Ни один компонент не открывает сокетов и не ходит в
  интернет; всё, что происходит, — локальные файлы и звуковое устройство.
- **Секретов нет.** `config/*.env` содержит только пути и параметры стенда;
  `.env` с чьими-либо секретами в Git не добавляется (`.gitignore`).
- **Акустический канал по определению не приватен**: передачу слышит и может
  записать любой в комнате. Шифрования в решении нет — SHA-256 доказывает
  **целостность** файла, но не подлинность отправителя и не
  конфиденциальность. Для секретных данных канал не предназначен.
- **Файлы пишутся только в каталог из `OUTPUT_DIRECTORY`**, и от имени файла
  берётся лишь его базовая часть (`Path(name).name`) — присланное имя вида
  `../../ключи.txt` не уведёт запись за пределы каталога.
- **Микрофон включается только с флагом `--audio`** и только на время
  сеанса; запись никуда не отправляется и по умолчанию не сохраняется.
