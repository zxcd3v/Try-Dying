# Методика и результаты тестирования

## Методика

Проверка идёт на четырёх уровнях — от чистых функций до двух настоящих
процессов. Звуковое железо не нужно нигде, кроме живых прогонов по воздуху:
всё воспроизводимо на любой машине одной командой.

| Уровень | Что проверяет | Где |
|---|---|---|
| Модуль | сетки тонов, полосы, кадрирование, кодирование/декодирование | `tests/test_profiles.py`, `test_bands.py`, `test_framing.py`, `test_tx.py`, `test_rx.py` |
| Канал | петля tx → канал-симулятор → rx: белый шум, дрейф часов ±0.1 %, эхо 50 мс | `tests/test_channel.py` (`modem/channel.py`) |
| Протокол | zlib → RS → NACK-цикл → SHA-256 через фейковый модем, порча канала | `tests/test_protocol.py`, `test_spool_modem.py`, `test_calibration.py` |
| Система | настоящие `recv.py` и `send.py` двумя процессами на общем линке, включая помехи и вердикты | `tests/test_cli.py` |

Итого **133 теста**, время прогона ~100 с:

```
PYTHONUTF8=1 python -m pytest -q
133 passed
```

Пороги SNR получены разведкой `python tools/snr_grid.py [robust|medium|fast]`
и закреплены регрессионными тестами: тест падает, если тюнинг сдвинул порог.
Скорость модема закреплена тестами в `tests/test_tx.py`.

## Пороги уверенного приёма и скорость

Порог — SNR, при котором партия принимается уверенно; скорость — байты
партии, делённые на длительность сигнала со всеми преамбулами и паузами.

| Профиль | Канал | SNR уверенного приёма | Скорость (модем) |
|---|---|---|---|
| robust (4-MFSK) | белый шум поверх тихого сигнала | **−9 дБ** | 16.9 Б/с |
| robust (4-MFSK) | шум + дрейф часов ±0.1 % + эхо 50 мс | **−6 дБ** | 16.9 Б/с |
| medium (16-MFSK) | оба канала | **−3 дБ** | 97.5 Б/с (5.8× robust) |
| fast (9 × 4-MFSK) | белый шум поверх тихого сигнала | **+12 дБ** | 308 Б/с (3.2× medium) |
| fast (9 × 4-MFSK) | шум + дрейф часов ±0.1 % + эхо 50 мс | **+21 дБ** | 308 Б/с |

Отрицательный порог означает, что шум **громче** сигнала: при −9 дБ шум
мощнее сигнала в 8 раз. Дрейф и эхо порог medium не двигают — его задаёт
различение тонов в шуме, а не поиск преамбулы.

## Полная таблица передач

Стенд `tools/bench.py` гоняет матрицу «3 профиля × 4 условия × 5 файлов»
(1 КБ–1 МБ, текст и случайные данные) через полный протокол и сводит
результаты в таблицу — **60 строк**:

- [docs/bench/results.md](bench/results.md) — markdown для отчёта;
- [docs/bench/results.csv](bench/results.csv) — те же данные машинно.

```
python tools/bench.py gen     # тестовые файлы (1 КБ–10 МБ) → out/bench/
python tools/bench.py auto    # авто-матрица: 3 профиля × 4 условия × 5 файлов
python tools/bench.py table   # перерендерить markdown из CSV
```

Условия: «чисто», «биты 0.2 %» (переворот каждого бита с вероятностью
0.002), «потеря кадров 10 %», «биты 0.2 % + потеря 10 %». Время авто-строк —
оценка эфира: точная длительность сигнала обеих сторон плюс 3 с на каждый
разворот полудуплекса.

Выдержка (полные данные — по ссылкам выше):

| Профиль | Файл | Условия | Время, с | Скорость, Б/с | Успех |
|---|---|---|---|---|---|
| robust | текст 10 КБ | чисто | 58.8 | 174.2 | 100 % |
| robust | текст 10 КБ | биты 0.2 % + потеря 10 % | 78.5 | 130.5 | 100 % |
| medium | текст 10 КБ | чисто | 30.0 | 341.4 | 100 % |
| medium | текст 10 КБ | биты 0.2 % + потеря 10 % | 45.8 | 223.5 | 100 % |
| fast | текст 10 КБ | чисто | 26.6 | 385.2 | 100 % |
| fast | текст 10 КБ | биты 0.2 % + потеря 10 % | 38.3 | 267.3 | 100 % |
| fast | случайные 1 МБ | чисто | 4146.0 | 252.9 | 100 % |
| fast | случайные 1 МБ | потеря кадров 10 % | 4764.6 | 220.1 | 100 % |

Главный вывод строк с помехами: **успех остаётся 100 %**, платой за помехи
становится время (+30…50 %), а не потеря данных. Текст идёт в разы быстрее
случайных данных того же размера — работает zlib.

## Живые замеры по воздуху

Живой замер добавляется в ту же таблицу одной командой, цифры берутся из
вердикта `send.py`:

```
python tools/bench.py manual --profile medium --file file.txt --size 3400 \
  --seconds 61.5 --distance 30 --noise "тихая комната" --ok 3 --tries 3
```

Повторный `auto` заменяет только свои строки и живые замеры не трогает.

**Состояние на момент сдачи:** строк «воздух» в таблице пока нет — живые
прогоны `--audio` проведены не полностью, галочки в тикетах 07, 09 и 10 не
проставлены. Всё, что в таблице, получено на канал-симуляторе и фейковом
модеме; выдавать это за замеры по воздуху мы не будем.

## Диагностика тракта перед живым прогоном

| Инструмент | Что показывает |
|---|---|
| `python tools/afr_sweep.py record\|play\|both` | АЧХ пары «динамик → комната → микрофон», уровень полосы каждого профиля относительно медианы; `out/afr.png` |
| `python tools/fast_probe.py record\|play\|analyze` | ошибки, отрыв тона и фон по каждой из 9 поднесущих fast |
| `python tools/mic_meter.py` | уровень входа, живой ли микрофон |
| `python tools/speaker_test.py` | тоны и chirp-преамбула на выход |
| `python tools/make_wav.py robust` | WAV и спектрограмма сигнала в `out/` — для доклада |

Провал полосы глубже ~15–20 дБ — повод сдвинуть частоты профиля или сменить
дистанцию. Как читать вывод зонда поднесущих — раздел «Диагностика тракта» в
[README](../README.md).
