# ADR-0002: Партия + NACK вместо stop-and-wait; каждый аир-кадр самодостаточен

Дата: 2026-07-24. Статус: принято (гриллинг, вопросы 4–5).

## Контекст

Исходный набросок команды предполагал подтверждение после каждого пакета (stop-and-wait). Также обсуждался «анонс размеров» будущих кадров в рукопожатии, чтобы не тратить место на заголовок в каждом кадре.

## Решение

1. Передатчик шлёт **партию** аир-кадров подряд; приёмник отвечает одним NACK со списком битых; повторяются только они (слой пары 2, контракт v1.1).
2. Каждый аир-кадр **самодостаточен**: своя chirp-преамбула, свой аир-заголовок с длиной (2 байта + CRC-8, повтор ×3, приём по большинству). Заголовок не сошёлся — кадр отбрасывается целиком, его добирает NACK-цикл.

## Альтернативы

- **Stop-and-wait** — отвергнут: каждый разворот динамик↔микрофон стоит ~0.5–1 с (преамбула ответа, защитные паузы, латентность аудиостека) → потолок ~150–250 Б/с даже в тишине, профиль fast теряет смысл.
- **Анонс размеров кадров наперёд** — отвергнут: создаёт единую точку отказа (потерян анонс — погибла серия), ломает слой «глупой трубы», экономит лишь ~30 мс на кадр. На уровне протокола эту роль уже играет HEADER-кадр пары 2.

## Последствия

Дрейф часов не накапливается (ресинхронизация каждым кадром). Потеря любого кадра локальна. Платим ~30 мс заголовка на кадр — осознанный размен скорости на надёжность (20 баллов против 15).
